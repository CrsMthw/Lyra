## [Unreleased]

### Added
- **Material 3 Expressive haptics** — app-wide tactile feedback with a single semantic vocabulary (`util/Haptics.kt`): `toggle(on/off)` for switch-like controls (shuffle, repeat, like, lyrics/visualizer, settings switches), `confirm`/`reject` for action outcomes (add/remove playlist, device transfer, sleep timer, delete confirm) and for selections/navigation (open playlist/Liked Songs, play a track, mini-player tap, collapse/expand panel + scrim tap, back buttons), `press` (ContextClick) for transport (play/pause/skip, incl. swipe-to-skip), for opening menus/secondary buttons (player ⋮ menu, device list, playlist ⋮, queue/share/add-to-playlist, settings gear, share, search FAB), for the menu items that open the sleep-timer and delete-playlist dialogs, and for the **Cancel** button on each of those confirmation dialogs, `longPress` for the song menu, `tick` for slider/seek notches (seek bar + volume), `scrollTick` (`ListScrollHaptics`) for list scrolling, and `threshold` (`PullThresholdHaptics`) for pull-to-refresh. Scroll haptics are **bottom-anchored** — one tick each time an item is revealed/hidden at the bottom edge of the viewport (the last visible item's index changes), so a tall hero/header at the top never creates a silent dead zone and tall rows never double-buzz; gated on an in-progress scroll so lazy-loading/appending items stays silent. Wired across player (full + pop-out + mini), Library, Search, Album, Artist, Queue, and Settings. All helpers are gated on a process-wide flag mirrored from a new **Settings → Haptic feedback** toggle (DataStore-persisted, default on, applies live with no restart); turning it off silences every helper.
- **Delete playlist** — an owned playlist's detail view now has a top-right overflow (⋮) menu with **Delete playlist**, guarded by a confirmation dialog; on confirm the playlist is deleted via `DELETE /playlists/{id}/followers` (Spotify models deleting your own playlist as unfollowing it), removed from the in-memory list and the library cache (`LibraryCache.removePlaylist`), and the detail view closes. Owned-only by design: Liked Songs and *Following* playlists show no ⋮; Featured suggestions aren't in the library. Works in both single-pane (folded) and two-pane (unfolded) layouts.
- **Song touch-and-hold menu** — long-pressing a track row (with a `LongPress` haptic) opens a Material 3 bottom sheet headed by the track's art + title/artist, offering **Add to playlist** (opens the existing add-to-playlist picker, with create-new), **Add to / Remove from Liked Songs** (label + heart flip in place, optimistic), **Remove from this playlist** (only when the row is in a playlist you own — drops the row immediately and updates the cached track list), and **Go to album / Go to artist**. Actions whose data is absent on the target are simply not shown (e.g. no "Go to album" within album detail; no remove outside an owned playlist). Available in Library (Liked Songs + playlists), Search results, Album detail (folded + two-pane), and the Queue (Now Playing card + upcoming items); the Artist screen lists only albums, so it has no track menu. Backed by a reusable `TrackActionsController` + `TrackActionsHost` (`ui/components/`) owned per screen ViewModel — it reuses the player's `PlaylistPickerState`/`AddToPlaylistResult` but operates on an arbitrary track rather than the currently-playing one. Known limitation (inherited from the player's sheet): the add-to-playlist ✓ marks reflect only playlists cached this session, so a playlist that contains the track but hasn't been opened may show unchecked; adding still works.
- **Device volume control** — the `DevicePickerSheet` now has a "Device volume" slider (drag-to-set, applied on release) flanked by volume-down/up icon buttons that step by 5%, controlling whichever Spotify Connect device is active; positioned directly under the "This device" card (above the device list) so it stays visible no matter how long the device list is; writes go to `PUT /me/player/volume` debounced 250 ms so a drag-release or a burst of ± taps coalesces into one call (well under the Web API rate limit). The control is enabled unless the active device positively reports `supports_volume: false` — so it correctly greys out when audio is on this phone via App Remote (the Web API can't set local device volume, even when the Z Fold 6 registers as a tablet while unfolded) while staying live for remote speakers/computers; rejected calls surface a transient toast (via the existing `deviceTransferError` channel) instead of silently doing nothing
- **Container transform — Library (single pane)** — selecting *Liked Songs* or any playlist (list rows and featured cards) now morphs that item's art seamlessly into the track-list hero instead of a hard slide; built with `SharedTransitionLayout` + `Modifier.sharedElement` keyed on a `lib-art-<id>` namespace (distinct from the nav-level `album-art` element), the bounds driven by the app's expressive `MotionScheme` so the art settles with a tasteful spring overshoot. The browser↔detail swap was softened to a fade-dominant transition so the overlaid morphing art carries the motion; reverses on back. Two-pane is unchanged (scopes are null there).
- **Expressive Motion pass** — `LyraTheme` already provided `MotionScheme.expressive()`, but custom animations used flat `tween`s; added `rememberArtBoundsTransform()` (`util/Motion.kt`) wrapping `motionScheme.defaultSpatialSpec` for shared-element morphs and routed spatial animations through the expressive springs so they settle with a tasteful overshoot:
  - **Album-art morphs now bounce** — every `album-art` shared element (mini player ↔ pop-out panel, panel → full player, mini → full player) carries the spring `boundsTransform`.
  - **Track-change art slide-in** — the incoming album art on skip/track-change settles via `defaultSpatialSpec` (the fling-*off* keeps its accelerating tween); applies to both `PlayerScreen` and the pop-out `PlayerCardContent`.
  - **Visualizer art-shrink** — the player art's grow/shrink when toggling the visualizer springs instead of `tween(400)`.
  - **Mini player & pop-out panel entrances** — slide-in/out now use the expressive spatial spring; the Library search-FAB offset uses `fastSpatialSpec`.
  - Colour/alpha cross-fades, wavy-indicator amplitude, the play/pause cookie spin, the seek-bar progress animation, and scroll-driven collapse intentionally stay non-springy (a bouncy progress bar or opacity would overshoot a valid range).
- **Home-screen widget (Now Playing)** — resizable Jetpack Glance widget with size-responsive layouts chosen from the actual size (`SizeMode.Exact`): **compact** (art + title/artist + play-pause), **small square** (square-ish — art + prev/play-pause/next, no text), **medium** (wide & short — art + title/artist + prev/play-pause/next), and **large** (album-art hero that scales to the widget size + title/artist), whose control row is adaptive — prev/play-pause/next when narrow, adding shuffle + repeat once the widget is ≥320dp wide so a tall-but-narrow widget never clips the outer two toggles; the compact↔medium width threshold is set above Medium's fixed footprint (320dp) so the title/artist column is never squeezed out by the three transport buttons — important on dense / unfolded home-grids where a widget can report a width that previously rendered art + buttons with no text; built on standard Material 3 (Glance `1.3.0-alpha01`; Material 3 Expressive is not yet renderable in widgets). Colours are seeded from the album-art palette while a track is present (same vibrant/dominant recipe as the player screen) and fall back to wallpaper/dynamic colours in the empty "Nothing playing" state; AMOLED honoured. State is mirrored from `PlayerStateManager` via an app-scoped collector into the widget's own Glance state (`updateAppWidgetState`/`currentState`), which is what drives recomposition (no second poller); album art is downsampled and palette-extracted once per track. Controls route through `LyraForegroundService` actions (`actionStartService`) so taps work cold without the process-death gap of a bare callback; whole-surface tap opens Lyra. Widget updates are skipped entirely when no widget is placed.
- **Synchronized lyrics** — full player screen (portrait and landscape) shows a synchronized, auto-scrolling lyrics view in place of the album art when enabled; preference persists to DataStore across app restarts; sourced from LRCLIB (lrclib.net) — a free, community-maintained LRC lyrics database; a separate OkHttp/Retrofit client (no Spotify token interceptor) is used; fetch strategy: exact `GET /api/get` by artist/title/album/duration, falling back to `GET /api/search` if not found; results cached in memory per track; pop-out panel and mini player are intentionally excluded
- **Synchronized lyrics display** — active line is bold `titleLarge` centered in the art area; surrounding lines fade with distance (65% / 35% / 18% alpha); `LazyColumn` auto-scrolls to keep the active line vertically centered; blank LRC lines rendered as spacers for musical pauses; plain-lyrics fallback (static scrollable `bodyLarge` text) when only unsynced lyrics are available
- **Audio visualizer** — `android.media.audiofx.Visualizer(0)` captures the global output mix and drives two reactive painters: `FftCWave` (smooth Akima-spline circular filled-disc that pulses outward past the art edge, with gravity-decay physics) pulsates behind the album art in `PlayerScreen` (portrait and landscape); `FftWave` (mirrored horizontal wave) overlays the bottom scrim in `QueueScreen`; toggled via the top-bar media menu Visualizer item; `RECORD_AUDIO` permission requested on-demand only when the user first enables it (never at launch); off by default, persisted in DataStore; degrades gracefully if permission is denied or revoked
- **Visualizer Settings toggle** — Settings → Player section has a dedicated Visualizer toggle to enable or disable the audio wave animation; persisted in DataStore; complements the existing toggle in the player top-bar media menu
- **Visualizer style picker** — Settings → Player now has a Circle / Bottom / Both selector (M3 `SingleChoiceSegmentedButtonRow`, revealed beneath the master toggle when the visualizer is enabled) choosing which surface(s) render: *Circle* = only the circular pulse behind the album art in the full player; *Bottom* = only the horizontal wave along the bottom of most screens (friendlier with the Android navigation bar); *Both* = both (default). Backed by a new `VisualizerStyle` enum persisted in DataStore; the bottom wave is gated app-wide via a single `LocalVisualizerBottomEnabled` CompositionLocal (alongside `LocalFftData`), and the player art only shrinks for the circle when Circle/Both is chosen. Capture (RECORD_AUDIO) is still gated solely on the master toggle, so Circle-only and Bottom-only both keep the capture running
- **Player top-bar media menu** — M3 Expressive `DropdownMenu` behind a `Tune` icon button in the player `TopAppBar`; replaces the earlier bottom-right `FloatingActionButtonMenu`; two `DropdownMenuGroup`s: first group has Lyrics (checkable) and Visualizer (checkable) as connected pill items; second group has Sleep Timer with active-timer supporting text; `containerColor = Color.Transparent` + `shadowElevation = 0.dp` on the outer `DropdownMenu` so M3's group pill surfaces render without a wrapping white elevated box
- **Create playlist** — "New playlist" row at the top of the add-to-playlist sheet opens a `BasicAlertDialog` with a creation form (name, description, public/private toggle); playlist is created via `POST /me/playlists` and the current track is added immediately; new playlist appears checked at the top of the list and is prepended to the library cache; accessible from both the full player screen and the pop-out panel

### Changed
- **Top app bar → floating controls (OneUI 8.5 style)** — the solid top app bar is being replaced by floating controls layered over edge-to-edge scrolling content (status-bar-to-nav-bar): a **top scrim** — the bottom-scrim recipe mirrored vertically (`verticalGradient(listOf(background, Transparent))`) — fades content under the status icons; a large **bottom-aligned hero title** in a uniform 300dp band (`HeroBandHeight`) scrolls away with the list; a small **title pill** fades in once the hero is gone (scroll-driven `alpha` via `graphicsLayer`, keyed on the hero item's scroll-out so there's no pop); and a **floating action pill** carries what used to be the bar's actions. The title pill and the action pill share one 52dp custom stadium so they read as a matched pair — `ui/components/FloatingTopControls.kt` (`TopScrim` / `TopActionPill` / `TitlePill` / `rememberHeroScrollProgress`). On sub-screens the back button is a floating pill at top-left with the title pill beside it. The M3 Expressive `HorizontalFloatingToolbar` was tried for the action cluster but it's sized for *bottom* toolbars (fixed ~64dp min height) and read too tall beside the title pill. Applied across the single-pane **Library**, **Queue**, **Settings**, **Album**, **Artist**, and the playlist/Liked-Songs track-list detail (sub-screens float a back pill at top-left with the title pill beside it, and an overflow/share pill at top-right); the unfolded two-pane layouts keep their previous bars for now.
- **Detail screens — compact M3 Expressive art hero** — the playlist/Liked-Songs, album, and artist detail screens (single-pane) share a new `DetailArtHero` (`ui/components/`): the art clipped to an M3 Expressive **4-sided cookie** shape (bordered, centred), with the title + subtitle on the left and **cookie-shaped action buttons** on the right — a **6-sided cookie** Play (accent) and a **4-leaf-clover** Shuffle (tonal). The subtitle is the track count (playlist), the artist names (album), or the follower count (artist); the artist screen has no buttons. Albums gain a **Shuffle** action (`PlayerViewModel.shuffleContext` — enables shuffle then plays the album context, mirroring playlist shuffle). This replaces the old full-width art header + the collapsing detail bar in single-pane; the playlist detail's container-transform morph was dropped (the small card → full hero morph fought the floating controls' z-order — plain slide+fade now).
- **Album-art background colour now "merges" with the cover (edge sampling)** — the player background gradient, the pop-out panel, the mini-player wash, and the home-screen widget background are tinted from the **average colour of the album art's outer border** instead of the Palette **Vibrant** swatch. Vibrant grabs the single most-saturated colour anywhere in the cover — often a minority splash in the *centre* (a shirt, lettering) that clashes; sampling the edge picks the colour the art is actually bordered by, so the cover appears to dissolve into the screen, closer to Spotify's now-playing background. The border average is **chroma-weighted** (a colourful minority on the edge outweighs a near-grey/black majority, so e.g. green smoke amid dark hair still reads as green), with a plain-average fallback when the border is essentially grey. Foreground accents that need contrast (sliders, like/shuffle/repeat tints, the visualizer wave, the mini-player progress ring) keep using the contrast-safe `surfaceAccent` — only backgrounds use the edge colour. The whole recipe (perimeter sampling + the Palette swatch chain) was centralised into one `util/AlbumArtColor.kt` (`Bitmap.albumArtColors(isDark)` / `loadAlbumArtColors(...)` / `Bitmap.perimeterColor()`), replacing the block previously copy-pasted across the player, pop-out panel, mini-player, nav graph, and widget.
- **Player add-to-playlist unified** — the full player and the pop-out panel now use the same `TrackActionsController` as the song touch-and-hold menu instead of a duplicate picker implementation in `PlayerViewModel` (which now delegates to it). Single source of truth for add / remove / create-playlist, so the player's add-to-playlist also inherits the surgical cache update and the live open-playlist refresh
- **Device picker "This device" hint** reworded to "Use this ONLY if your device isn't in the list below…" so it reads as a fallback rather than the default playback target
- **Player media menu toggle behavior** — Lyrics and Visualizer items no longer dismiss the menu on tap; menu stays open so both can be toggled without reopening; only the Sleep Timer item dismisses (it opens a dialog)
- **Player media menu checked state** — leading icon swaps to `Icons.Default.Check` when active (trailing checkmark was removed — it caused the menu width to expand on toggle, shifting the layout); `selectedContainerColor` is `surfaceAccentColor.copy(alpha = 0.15f)` for a subtle album-art-matched tint instead of a solid fill
- **Secure storage** — `EncryptedPrefs` migrated from the deprecated `androidx.security.crypto.EncryptedSharedPreferences` to a direct Android Keystore implementation; each value encrypted with AES-256-GCM (randomised IV, 256-bit key, 128-bit GCM tag) and stored as Base64 in standard `SharedPreferences`; `security-crypto` dependency removed entirely; **note**: stored credentials (Client ID + tokens) are cleared on first launch after this update — re-enter your Spotify Client ID and reconnect once
- **Dependency updates** — Material3 `1.5.0-alpha20` → `1.5.0-alpha21`; `core-ktx` `1.18.0` → `1.19.0`
- **`PlayerPanelHost` screen height** now reads from `LocalWindowInfo.containerSize` instead of the deprecated `LocalConfiguration.screenHeightDp`, consistent with the window-size-class API used elsewhere for adaptive layout
- **Circle visualizer beat-snap rotation** — on each energy spike detected in `FftCWavePainter`, the FFT band array is rotated by a random offset (25–67% of the circle) before mapping to the disc, so the bass bulge blooms from a different position on the circle each beat; beat detection uses an exponential moving average of per-frame RMS energy with a 1.6× threshold and 300 ms cooldown; `FftWavePainter` (bottom wave) is unaffected — both painters receive the same raw FFT bytes independently
- **Visualizer animation model** — `GravityModel` rewritten from physics-decay (`dy`/`ay` per-frame gravity) to a held-target asymmetric envelope (ATTACK=0.35, RELEASE=0.06); each band holds its target between FFT updates instead of decaying, eliminating the jitter caused by the 43 Hz FFT / 120 Hz render mismatch; silence detection zeros all targets when no non-quiet data arrives for >100 ms, letting the release curve drain bars smoothly to zero
- **Frequency tilt** — `applyFrequencyTilt` ramps gain linearly from 1× (lowest bin) to 5× (highest bin), applied after the power transform in the circular painter and before mirroring in the wave painter; high-frequency detail now remains visible during heavy bass passages instead of being drowned out
- **Visualizer accent color** — all `FftWaveCanvas` instances now use the palette-derived `surfaceAccentColor` (via `LocalVisualizerAccentColor` CompositionLocal provided in `LyraNavGraph`) instead of `onAccentColor`; consistent with the circular visualizer color across all screens: Library, Album, Artist, Search, Player, and Queue
- **Landscape player layout is now dynamic** — art size uses `minOf(maxWidth, maxHeight * 0.82f)` so it shrinks automatically on height-constrained screens (e.g. folded landscape) without a separate UI branch; controls column replaced `Column + verticalScroll` with `BoxWithConstraints`; spacers between controls sections are proportional to available height (`spacingLarge = maxHeight * 0.04f` clamped to 6–16dp, `spacingSmall = maxHeight * 0.03f` clamped to 4–12dp) so the full controls UI fits without scrolling on any landscape phone

### Removed
- **Liked Songs manual refresh** removed from Settings → Storage — pull-to-refresh on the track list covers this

### Fixed
- **Playlist tracks duplicated when reopening a playlist** — opening a playlist repeatedly could double its track list (10 → 20 → 30 …), the header flashing the doubled total before settling back. The `TrackList` auto-fires `onLoadMore` the instant a short list "reaches bottom", which raced `selectPlaylist`'s async cache load: `loadMore` fetched page 0 and appended it onto the just-loaded cached list, then **persisted** the doubled list, so it compounded on every open (a pull-to-refresh reset it). Exposed by the track-count fix above — before it, the initial `total` was 0 so `canLoadMore` was false during that window and the race couldn't fire. `loadMorePlaylistTracks`/`loadMoreLikedSongs` now bail while `isLoadingTracks` is true, so pagination can't fire until the initial load settles; legitimate scroll-to-load is unaffected.
- **Playlist track count drifted after an in-app add/remove** — adding/removing a track in-app updated the cached track list but not the library's `/me/playlists` metadata count, so the My Playlists card (left pane) and the detail header (right pane) disagreed until a full library refresh — and Spotify's playlist-metadata count is itself eventually-consistent (it lags the real total for a while, so even a refresh could briefly show the old number). The surgical cache methods (`appendToPlaylistTrackList`/`removeFromPlaylistTrackList`) now also mirror the metadata count to the new cached size — an **absolute** value, never a ±1 delta that would compound existing drift — and ping the cache revision so the My Playlists list re-syncs; both panes update instantly on an in-app change. On open, a lightweight `limit=1` reconcile heals any remaining drift and picks up changes made on other devices, using `maxOf(serverTotal, loadedCount)` so a lagging server total can never drag the count below what's actually loaded. The **"Remove from this playlist"** action was also routed through that same single cache method — it previously hand-rolled its own `saveTrackList`, which skipped the count sync and left the cache one short of the metadata, silently no-op'ing the *next* add.
- **Stale auto-generated mosaic hid Spotify's real playlist cover** — a playlist created with no Spotify art gets a local 2×2 mosaic, but once Spotify generated a real cover the mosaic kept winning forever, because `PlaylistCard` and the detail header preferred the mosaic file over `playlist.thumbnailUrl`. Flipped the priority: Spotify's `thumbnailUrl` is shown when present, with the mosaic as a fallback only when Spotify has no art yet — so a brand-new playlist still gets the instant local mosaic, then switches to Spotify's cover once it exists and the library is refreshed.
- **Playlist track counts were always 0 (Spotify renamed the field)** — every playlist in the library list showed the owner's name instead of a track count, and the detail header briefly showed the wrong number, because `GET /me/playlists` now returns the per-playlist count under `"items": {href, total}` instead of the old `"tracks"` key — so `SpotifyPlaylist.tracksMeta` never parsed and `trackCount` was always 0. Mapped `@SerializedName(value = "items", alternate = ["tracks"])` (legacy `tracks` kept as a fallback). Now the list shows real counts — **My Playlists** shows count-only (you're the owner) and **Following** shows **"Owner · N tracks"** — and the detail header shows the correct total from the first frame. (A lightweight per-open `limit=1` reconcile was later re-added — see "Playlist track count drifted after an in-app add/remove" below — to heal drift from in-app edits and changes made on other devices.)
- **No toasts while the pop-out player panel was open** — add-to-playlist results, device-transfer failures, and player errors are shown as Android `Toast`s, but the toast effects lived only in `PlayerScreen` (the full player, used on narrow screens). On wide / unfolded screens the pop-out `PlayerCardContent` is shown *instead of* it and had no toast logic, so any action taken from the panel produced no toast. Mirrored the three toast effects into `PlayerCardContent` (they're mutually exclusive with the full player in steady state, so nothing double-toasts).
- **Search screen slid under the side navigation bar in landscape** — the search bar and results applied no horizontal window insets, so in landscape (nav bar on the side, e.g. folded) the back button / text field and result rows ran underneath it. Added `WindowInsets.navigationBars.only(WindowInsetsSides.Horizontal)` padding to the top bar and content, matching every other screen; portrait is unchanged (zero horizontal inset there).
- **New playlist didn't appear in the library until pull-to-refresh** — creating a playlist from the song touch-and-hold menu or the player's add-to-playlist sheet wrote it to the cache but not the in-memory list the browser renders, so it stayed hidden until a manual refresh. `LibraryCache` now exposes a revision `StateFlow` (bumped on `prependPlaylist`/`removePlaylist`, never on a plain save) that `LibraryViewModel` collects to re-sync its playlist list from the cache — the new playlist shows at the top immediately, no matter which screen created it.
- **Adding/removing a song to an owned playlist didn't show until pull-to-refresh** — opening the playlist served a cached track list whose snapshot still matched the (equally stale) library metadata, hiding the change. Add/remove now **surgically** update the cached track list (append to the end / filter the row out, keeping the snapshot id — same idea as Liked Songs) so re-opening reflects it with no refetch. A new `LibraryCache.trackListChanges` signal additionally **live-refreshes the playlist while it's open**, covering every entry point: the song menu, the full player, the pop-out panel, and album detail (album rows now carry a reconstructed full track so they refresh too). To protect lazy-loading, the surgical append is skipped when a playlist's cache is only partially paged (the new track loads on scroll instead) — splicing into a partial prefix would duplicate or misorder rows.
- **Device picker sheet opened then collapsed** — the `DevicePickerSheet` briefly opened expanded, then settled into its half-height partial detent a moment later, clipping off the bottom of the device list (and the volume control beneath it) whenever the list just barely filled the partial height. It now opens fully expanded and stays there — the sheet state is restricted to Hidden↔Expanded (no partial detent) via the non-deprecated `rememberBottomSheetState`.
- **Playlist track lists capped at 50 / wrong count** — opening a playlist only ever loaded the first 50 tracks with no way to see the rest; now they lazy-load on scroll exactly like Liked Songs (`LibraryViewModel.loadMorePlaylistTracks` + `playlistTracksOffset`/`playlistTracksTotal`, wired through `TrackList`'s existing `canLoadMore`/`onLoadMore`). The page offset advances by the **raw** page size (not the playable-filtered count) so playlists with unavailable tracks don't re-fetch or duplicate rows; pull-to-refresh resets paging cleanly. The detail-header track count now reads the authoritative `playlistTracksTotal` instead of the loaded-track count, so it shows the real total immediately instead of "50" until you scroll to the bottom.
- **Visualizer didn't react over Bluetooth headphones** — a `Visualizer` binds to the audio output route that was active when it was created, and returns silence once the route changes (e.g. speaker → Bluetooth A2DP); since `VisualizerManager` created the instance once and never re-bound it, switching to BT mid-session (or having it connected after the instance was made) left the visualizer flat — yet enabling it *fresh* while already on BT worked, which ruled out the platform A2DP-offload limitation and pinned it on the stale instance. `VisualizerManager` now registers an `AudioDeviceCallback` and re-creates the capture when the output device set changes (debounced 400 ms so the new route settles first), and a `routeDirty` flag recreates on the next `start()` if the route changed while paused. Re-binds correctly across speaker↔Bluetooth in both directions.
- **Visualizer kept moving on quiet/silent audio; was also volume-dependent** — the `Visualizer` ran in its default `SCALING_MODE_NORMALIZED`, which auto-gains every frame so the loudest bin sits at full scale; on a quiet or audibly silent track this amplified the noise floor into constant motion (and defeated the silence gate, which never saw a low value). Reworked the gain pipeline to mirror how ProjectM/Milkdrop behave: the capture now runs in `SCALING_MODE_AS_PLAYED` (raw magnitudes track the true output level, so silence reads ~0 — measured exactly `0.0` when paused), and a new `Agc` (automatic gain control, one instance per painter) normalizes each frame against a slowly-released rolling peak so the visualizer looks equally lively at any volume (100% vs Samsung's 150% both converge to the same amplitude) instead of being dead when quiet. A smoothstep soft-gate keyed on the *true* level keeps genuine silence flat — because the gate runs on the raw AS_PLAYED magnitudes, the AGC can never amplify the noise floor back into motion. Beat detection stays on the raw (volume-invariant) magnitudes. Thresholds were set from on-device measurement of the actual magnitude scale (silence `0.0`, quiet ≈ `6–34`, loud ≈ `80–168`) at the device's 10 Hz FFT rate.
- **Folded-landscape player rotation crash** — rotating to landscape on the full player crashed with `IllegalArgumentException: maxWidth must be >= minWidth` from Material 3's `ButtonGroupMeasurePolicy`: the Queue/Share/Add action bar used an M3 `ButtonGroup` with overflow disabled (empty `overflowIndicator`/`menuContent`), and its overflow measure computes a negative width when the controls column is tight. Replaced both the full-player and pop-out-panel button groups with a plain `Row` of the same connected-shape (`ButtonGroupDefaults.connected*ButtonShape`) tonal icon buttons — identical at rest, but a `Row` clips instead of producing inverted constraints. (Trade-off: loses the ButtonGroup interactive press-squeeze; the overflow feature was unused.)
- **Album-art morph was one-directional into the player** — opening the full player from a detail page (Album/Artist) morphed the art into the mini player, but navigating *back* did not morph it home. Two causes: on **narrow** screens the mini player registered the `"album-art"` shared element twice in the nav scope (primary + secondary both resolving to the nav scope), which resolved ambiguously and broke the morph on pop; on **wide** screens the secondary nav scope was gated on `transition.isRunning`, which never catches the exiting element on a back/pop (a shared element added after a pop begins is too late to be the exit participant). Fixed by registering the mini's nav scope once on narrow, and *continuously while the pop-out panel is fully closed* on wide (driven by the panel's own `Transition` so it can't desync from the panel slide) — so the element exists before any pop starts. Morphs both directions now in folded portrait, folded landscape, and unfolded.
- **Album art popping in late on track change (full player & pop-out panel)** — the art container slid into place before its image had loaded, so on a cold (non-memory-cached) image the art would appear partway through the slide or just snap in at center. The art now loads through a `crossfade(200)` request: Coil skips the crossfade on memory-cache hits (already-loaded art still shows instantly) and fades cold art up instead of popping. The request is `remember`ed on the art URL so the per-second progress tick doesn't rebuild it; the slide/shared-element animation code is unchanged.
- **Settings screen missing bottom fade scrim** — `SettingsScreen` had `navigationBarsPadding()` applied directly to the scrollable `Column` with no `Box` wrapper, so there was no overlay surface for the scrim; restructured to wrap in a `Box`, removed `navigationBarsPadding()` from the `Column`, added a matching bottom `Spacer(scrimHeight)`, and overlaid the `Brush.verticalGradient` scrim `Box` at `Alignment.BottomCenter`, consistent with all other scrollable screens
- **Bottom visualizer clipped to right pane on Album Detail and Artist Detail wide screens** — `FftWaveCanvas` was placed inside the right card's `Box`, so it only covered 58% of the screen width; moved to an outer `Box` wrapping the full `Row` so it spans both panes at full width, matching the Library screen layout; right-card scrim now fades to `surface` instead of `background` to match the Card's background color
- **Shuffle and repeat buttons misaligned with skip buttons** — the dot indicator was placed in a `Column` below the `IconButton`, making the Column's layout height 53dp (48dp button + 5dp dot) vs the 48dp skip buttons; the Row's `verticalAlignment = Alignment.CenterVertically` was centering the Column's midpoint instead of the icon's midpoint, pushing shuffle/repeat ~2.5dp too high; fixed by wrapping in a `Box` instead — the dot overlays with `align(Alignment.BottomCenter).offset(y = (-5).dp)` outside the layout flow so the Box reports 48dp height, matching the skip buttons; applies to both `PlayerScreen` and `PlayerCardContent`

- **Album art** morphs between the mini player and the full player screen when navigating via album/artist name taps (folded and unfolded)

- **Background liked-songs fetcher**: while music is playing (notification visible), Lyra quietly fetches one page of liked songs every 30 seconds into the library cache until the full library is indexed; the fetcher respects Spotify's rate-limit window and backs off on 429
- **Like/unlike** from the player now surgically updates the liked-songs cache (prepend on like, remove on unlike) without invalidating or re-fetching the full list; external likes/unlikes are detected by count diff on next library open — new songs prepended in one API call, removed songs trigger a full refetch

### Changed
- **Pull-to-refresh** on liked songs now preserves background-fetch progress beyond page 1 instead of overwriting the full cache with only 50 tracks

### Fixed
- **Album track count** now reads "1 song" instead of "1 songs"
- **Playlist thumbnails** not showing in the library browser — Spotify's thumbnail URL was available on every playlist object but `PlaylistCard` and `PlaylistListCard` only ever rendered a mosaic or a blank icon; both now fall back to the Spotify thumbnail when no mosaic exists, with mosaic generation skipped entirely for playlists that already have Spotify art
- **Queue screen crash** when shuffle is on with a small playlist — Spotify's queue API repeats the same track multiple times in the response; duplicates are now filtered out before display
- **Shuffle and repeat** active state now shows a small dot indicator below the button (both full player and pop-out panel), matching Spotify's own affordance; the previous color-only tint was hard to read against many album art colors
- **Launch crash** after adding `albumType` field to `SpotifyAlbum` — Gson bypasses Kotlin non-null defaults on deserialization, leaving the field `null` on cached tracks and crashing `hashCode()`; fixed by making the field nullable
